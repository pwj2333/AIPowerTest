# AI 能力认证

AI 能力测评 Web 应用。

## 运行

```bash
npm ci
npm run dev
```

Windows 也可以双击 `run-local.cmd`；首次运行会自动安装依赖并打开浏览器。

开发数据写入 `data/assessment.json`。该目录已被 Git 忽略，不会把真实人员和答卷提交到仓库。

打开终端输出的本地地址：

- `/`：员工输入姓名后进入当前开放的测评
- `/admin`：管理员工作台
- 首次使用先在管理员工作台创建测评批次，再导入人员

## 已实现

- 20 道经重新措辞的工作情景题、连续能力分、8 个等级、四维能力分布、置信度和高等级复核提示
- 员工直接输入姓名；未找到或存在重名时提示联系管理员
- 部门和岗位只取自管理员导入的 CSV，员工端不能自行修改
- 题目轨迹、稳定随机选项顺序、选择反馈、切题动效、自动保存、一次提交、个人结果和行动任务
- 管理员可上传、在线编辑、校验、预览、保存和下载 Markdown 题库
- 管理员端展示原始分直方图、标准差、偏度和 Jarque-Bera 指标；少于 30 份答卷时不会判断分布形态
- 当前题库版本会按题计算平均难度、四档选项分布和校正题总相关，自动标记过易、过难与低区分度题
- 正式存储默认为空，不会自动创建任何人员、批次或答卷

## Markdown 题库格式

每道题由一个二级标题、一行题干和四个计分选项组成。题库必须覆盖 `L1`–`L8` 和 `office`、`scenario`、`workflow`、`innovation` 四个维度。

```markdown
## q1 | L1 | office | 任务启动
> 回想最近一次需要快速起草工作文案，你实际怎样开始？
- [0] 没有使用 AI，直接沿用旧材料或从头写。
- [1] 向常用 AI 输入一句任务要求，再边看边补充。
- [2] 先写清受众和交付物，再让 AI 生成一版。
- [3] 先确定验收样例、事实边界和输出格式，再提交任务。
```

题目无法在没有真实样本的情况下保证答卷呈正态分布。当前版本减少了选项位置和理想答案提示，并用连续总分避免单项门槛造成堆积；正式使用时应收集至少 30 份有效答卷后检查分布，较可靠的题目区分度分析通常需要更大的代表性样本。

## JSON 数据存储

批次、人员、草稿、答卷和题库由 `server.mjs` 统一保存到 JSON 文件。默认路径为 `data/assessment.json`，可通过 `DATA_FILE` 环境变量修改。服务器串行合并不同用户的增量变更，并通过临时文件原子替换，避免并发提交互相覆盖或写出半个文件。

生产构建可直接运行：

```bash
npm run build
npm start
```

Docker 镜像使用 `/app/data/assessment.json`，部署工作流会挂载命名卷 `ai-power-test-data`，替换容器不会删除数据。需要定期备份该卷；不要同时启动两个容器写同一个 JSON 文件。姓名核验状态仍只保存在当前浏览器会话中。

管理员工作台使用服务端密码和 8 小时的 `HttpOnly` 会话。默认密码为 `admin123`，生产部署可通过 `ADMIN_PASSWORD` 环境变量或同名 GitHub Actions Secret 修改。连续输错 5 次会锁定当前地址 15 分钟。

正式公网开放时仍应配置 HTTPS 和企业网关访问控制。
